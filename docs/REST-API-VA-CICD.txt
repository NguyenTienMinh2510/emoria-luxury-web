EMORIA — REST API và CI/CD (18/09/2026)

Kiến trúc đang dùng
React SPA → /api/v1/... (Vercel Node function) → Supabase PostgreSQL/RPC.
Supabase Auth và Storage vẫn dùng SDK trực tiếp: đăng nhập, refresh token, upload
video/ảnh. RPC nằm ở backend để giữ transaction, giá từ database, chống trừ kho
hai lần, phiên bản kỷ vật và RLS. Không cần tạo một server Express chạy 24/7.
Không xóa database hoặc đổi ID sản phẩm/đơn/kỷ vật khi triển khai bản này.

Các file chính
- api/v1.js: HTTP routing, JSON, giới hạn body, xác thực JWT, quyền admin, lỗi HTTP.
- server/routes.js: danh sách endpoint cụ thể và ánh xạ nghiệp vụ database.
- src/services/apiClient.js: gọi API cùng origin, gửi Bearer token hiện tại.
- src/services/*Service.js, articlesApi.js: hợp đồng dữ liệu cho UI.
- src/services/checkoutPayload.js: bỏ giá/tổng tiền/quyền tự khai từ client.
- src/services/bankTransfer.js và components/BankAppPayment.jsx: link ngân hàng.
- .github/workflows/ci.yml: kiểm thử/build trên GitHub.
- vercel.json: rewrite REST và chặn build deploy nếu test thất bại.

Hợp đồng HTTP
Base URL: /api/v1. JSON request/response. Authorization: Bearer <access_token>.
Không đặt token đăng nhập, PIN hoặc grant vào query string.
Response thành công giữ DTO của nghiệp vụ; danh sách quản trị trả array.
Lỗi: {"error":{"code":"HTTP_401","message":"Vui lòng đăng nhập."}}.
Mã: 400 dữ liệu yêu cầu sai, 401 thiếu/hết phiên, 403 thiếu quyền, 404 sai route,
405 sai method (có Allow), 409 nghiệp vụ từ chối/xung đột, 413 body quá lớn,
415 sai content type, 422 dữ liệu database không hợp lệ, 503 DB chưa trả kết quả.
Mọi response no-store. POST tạo tài nguyên thành công trả 201.
Body tối đa 512 KiB; media upload trực tiếp Storage theo RLS.
API dùng public key + JWT người gọi, không dùng service-role để bỏ qua RLS.
Không có endpoint gọi tùy ý một tên RPC/bảng do client cung cấp.
Các quyền/RPC Supabase gốc được giữ để đảm bảo tương thích và bảo vệ ở DB.

Đặt hàng: gửi customerName,phone,email?,address,city?,note?,paymentMethod,
hasGiftBox?,items:[{id,size,quantity,isGift?}],requestId.
Không gửi giá/tổng tiền để tính tiền. API loại các trường này, DB tính lại.
Khi timeout/5xx: giữ nguyên requestId VÀ payload để gửi lại; không tạo UUID mới.
Khi 4xx: hiển thị lỗi; sửa dữ liệu theo giao diện trước khi gửi yêu cầu mới.
Tra cứu bằng mã đơn chỉ trả tiến trình công khai. JWT chủ đơn/admin hoặc mã
tra cứu/số điện thoại đúng mới trả thông tin người nhận và chi tiết đơn.
PATCH profile chỉ đổi trường được gửi; trường bỏ qua được giữ nguyên.

Các API tích hợp hiện hữu được giữ URL
GET  /api/analytics?days=7|30|90 — GA4, JWT admin, credentials Google chỉ ở server.
POST /api/memory-media — ký URL media sau khi xác thực grant/quyền xem.
POST /api/sepay-webhook — API key riêng, server đối soát chuyển khoản.

am lấy tổng tiền trả từ server. BIDV áp dụng giới hạn ghi chú alphanumeric nên
deeplink dùng mã đối soát rút gọn dạng EMO + 20 ký tự hex (23 ký tự, không dấu
gạch); webhook tự tìm về mã đơn đầy đủ EMO-... và QR hiển thị cùng mã rút gọn.
Mã đơn đầy đủ vẫn hiển thị trên xác nhận/tra cứu; tn không phải bằng chứng thanh toán.
bn tên chủ tài khoản.
url quay lại web tra cứu đơn, không mang lookupToken/PIN.

CI và CD
1. PR hoặc push main → GitHub Actions chạy npm ci, npm run test:ci, npm run build.
2. Bộ test CI dùng mock/fixture, không cần secret Supabase/Google/SePay thật.
3. Vercel Git Integration tiếp tục deploy từ main như trước. buildCommand chạy
   npm run test:ci && npm run build; test lỗi thì bản mới không được phát hành.
   Bản production thành công trước đó tiếp tục phục vụ.
4. Hai nền tảng có thể chạy song song. Không khẳng định Vercel đợi trạng thái
   GitHub Actions: Vercel tự chạy cùng bộ test trong bước build của nó.
5. Nên bật branch protection/ruleset cho main, yêu cầu check “Test and build”
   trước khi merge PR. File workflow không tự bật được quy tắc repository.
6. Không cần chép service-role/GA4 private key vào GitHub để chạy pipeline này.
   Production dùng biến môi trường hiện có ở Vercel. Không chạy SQL migration
   tự động trên production trong workflow này.
7. Khi tạo lại project Vercel, chọn Node 22 trở lên, Framework Vite, giữ
   vercel.json và không ghi đè Build Command bỏ bước test.

Kết quả kiểm thử trước bàn giao
- API: tất cả route cần user/admin từ chối đúng quyền; không dùng service-role;
  requestId không đổi, giá client bị bỏ, private token nằm trong body.
- Local REST + database: đặt đơn/gửi lại/tra cứu, webhook trùng không cộng tiền
  hai lần, paid vẫn chờ admin duyệt, vận chuyển, profile, bài viết/comment,
  PIN và version kỷ vật, admin không mở thư riêng chỉ nhờ role.
- Render: trạng thái đăng nhập, biểu đồ GA4 và component link ngân hàng.
- Chưa thể kiểm chứng thao tác autofill trên app ngân hàng thật bằng desktop.

Lưu ý tiếp tục phát triển
Không cần chuyển sang microservices. Thêm route resource trong server/routes.js,
gọi qua apiClient, giữ transaction quan trọng trong SQL, và thêm regression test
cho thay đổi có rủi ro. Cần đo hiệu năng thật trước khi thêm cache/mở rộng hạ tầng.
